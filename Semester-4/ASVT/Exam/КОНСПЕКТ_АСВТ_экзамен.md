# БЛОК 1. Начало курса (вопросы 1–18)

## 1. Представление информации в ЭВМ (понятие информации, виды систем счисления, способы представления чисел со знаком и примеры, способы представления вещественных чисел и примеры, методы кодирования информации: текст, графика, звук/видео).
- **Информация** (3 трактовки):
  - **в обиходе** — данные/факты, представляющие интерес;
  - **в технике** — сообщения в форме знаков или сигналов;
  - **в кибернетике** — часть знаний для ориентирования, активного действия, управления.
- В ЭВМ информация кодируется двоичными сигналами (0/1).
- **Система счисления (СС)** — способ записи чисел знаками. Три класса:
  - **непозиционные** — древние;
  - **позиционные** — вес цифры зависит от позиции (2-, 8-, 10-, 16-ричная);
  - **смешанные** — напр. римская.
- **Числа со знаком** (n разрядов, старший — знаковый: 0 = «+», 1 = «−»):
  - **Прямой код** — знак + модуль. Минус: два нуля (+0 и −0), сложно вычитать.
  - **Обратный код** — для отрицательных инвертируются все разряды. `a + (−a) = 2ⁿ − 1`.
  - **Дополнительный код** — обратный + 1. `a + (−a) = 2ⁿ`. **Главный**: вычитание заменяется сложением, один ноль. Используется в АЛУ.
- **Вещественные числа:**
  - **С фиксированной точкой** — точка на заданном месте, простой, но малый диапазон.
  - **С плавающей точкой** — `±M · qᵖ` (мантисса M, порядок p, основание q). Стандарт **IEEE 754**: знак, порядок (смещённый), мантисса. Широкий диапазон.
- **Кодирование** (статическое и динамическое):
  - **статическое — текст:** таблицы кодировки (ASCII 8 бит, **Unicode/UTF-8**);
  - **статическое — графика:** растровое и векторное;
  - **динамическое — звук/видео:** преобразование аналог→цифра (АЦП) + сжатие (кодеки).

## 2. Этапы развития вычислительной техники, классификация ВМ (этапы информатизации, поколения ЭВМ: элементная база, ключевые черты, классификация ВМ).
- **Исторические этапы информатизации** (фактор → период):
  - технический (структура/архитектура ЭВМ) — 1946–64;
  - программный — 1954–70;
  - информационный (структуры данных) — с 1970;
  - гуманитарный (интерфейсы) — с 1990.
- **Поколения ЭВМ (по элементной базе):**

| Пок. | Годы | База | Черты |
|------|------|------|-------|
| 0 | 1642–1945 | механика, реле | Паскаль (1642), Лейбниц, Бэббидж, Z3 |
| 1 | 1945–1953 | электронные **лампы** | 10²–2·10⁴ оп/с, ОЗУ на ферритах, машинный код |
| 2 | 1954–1962 | **транзисторы** | 10³–10⁵ оп/с, печатный монтаж, языки выс. уровня |
| 3 | 1963–1972 | **интегральные схемы** | 10⁶ оп/с, ОС (разделение времени), сети |
| 4 | 1972–1984 | **большие ИС (БИС)** | 10⁶–10⁸ оп/с, микропроцессоры, идея RISC |
| 5 | 1984–1990 | **СБИС** | многопроцессорные ВС, ЛВС, суперЭВМ |
| 6 | 1990–… | СБИС | параллелизм, сети |

- **Классификация ВМ:**
  - по принципу действия: механические, электрические (ЭВМ), оптические, пневматические, гидравлические;
  - по форме представления информации: аналоговые (АВМ), цифровые (ЦВМ), гибридные (АВМ+ЦВМ);
  - по назначению: широкого назначения, проблемно-специализированные, узкоспециализированные.
- ЭВМ и системы: обычные ЭВМ · суперкомпьютеры (многопроцессорные ЭВМ) · вычислительные системы. **Отличие ВС от ЭВМ — в числе вычислителей.**

## 3. Назначение и характеристики элементарных узлов ЭВМ (вентили, триггеры, сумматоры, счётчики, компараторы, шифраторы/дешифраторы, мультиплексоры/демультиплексоры, ЦАП/АЦП – назначение и краткое описание всех узлов).
*Схему рисовать не требует — только назначение. Можно один пример (напр. вентиль).*
- **Вентиль (логический элемент)** — реализует булеву функцию (И, ИЛИ, НЕ, И-НЕ, ИЛИ-НЕ, XOR). Базовый кирпич схемотехники.
- **Триггер** — элемент памяти на 1 бит, имеет 2 устойчивых состояния (RS, D, T, JK).
- **Сумматор** — сложение двоичных чисел (полусумматор, полный сумматор с переносом).
- **Счётчик** — подсчёт импульсов / хранение числа, +1 каждый такт (суммирующий, вычитающий, реверсивный).
- **Компаратор** — сравнение двух чисел (=, <, >).
- **Шифратор / дешифратор** — преобразование кода: позиционный код ↔ двоичный (дешифратор активирует один выход по входному коду).
- **Мультиплексор / демультиплексор** — MUX выбирает один из N входов на общий выход по адресу; DEMUX — наоборот, направляет вход на один из N выходов.
- **ЦАП / АЦП** — преобразование цифра↔аналог: ЦАП цифровой код → напряжение, АЦП напряжение → цифровой код (дискретизация + квантование).

## 4. Специализированные интегральные схемы (схема ПЛМ, типы компонентов FPGA, принципы работы программируемых элементов FPGA: SRAM-based, antifuse, flash).
*Нужна **схема ПЛМ**.*
- **ПЛМ (программируемая логическая матрица)** — две программируемые матрицы: матрица «И» (формирует конъюнкции входов) → матрица «ИЛИ» (суммирует их). Реализует любую булеву функцию в ДНФ.

```
входы ──►┌─────────┐ произведения ┌──────────┐──► выходы
          │матрица И │─────────────►│матрица ИЛИ│
x1..xn ─►│ (AND)  │ (термы)   │ (OR)  │─► f1..fm
          └─────────┘       └──────────┘
```

- **FPGA** — ПЛИС с программируемой логикой. Компоненты: **логические блоки (CLB)** с LUT-таблицами и триггерами, **программируемые межсоединения**, **блоки ввода-вывода (IOB)**, блоки памяти, умножители.
- **Программируемые элементы (как хранится конфигурация):**
  - **SRAM-based** — конфигурация в статической памяти. Перепрограммируемые, но энергозависимые (теряют прошивку при выключении, нужна загрузка из ПЗУ). Самые распространённые.
  - **Antifuse** — однократно программируемые (перемычка «прожигается»). Энергонезависимые, надёжные, но не перепрошиваются.
  - **Flash** — на флеш-ячейках. Энергонезависимые и перепрограммируемые (компромисс).

## 5. Архитектуры ЭВМ и принципы фон Неймана (уровни детализации структуры ВМ, принципы фон-неймановской концепции, структура фон-неймановской ВМ, виды архитектур ЭВМ).
*Нужна **структура фон-неймановской ВМ**.*
- **Уровни детализации структуры ВМ (7, сверху вниз):** языки высокого уровня → ассемблер → ОС → архитектура системы команд → микроархитектура → цифровой логический → физический (транзисторный).
- **Принципы фон Неймана:**
  1. **Двоичное кодирование** данных и команд.
  2. **Программное управление** — программа из команд, выполняемых последовательно.
  3. **Однородность памяти** — команды и данные в одной памяти, неразличимы по виду (команду можно обрабатывать как данные).
  4. **Адресуемость памяти** — память из ячеек с адресами, доступ по адресу.

```
        ┌─────────────────────────────┐
        │      ЦП (CPU)     │
        │ ┌─────┐    ┌────────┐ │
        │ │ УУ │◄──────►│ АЛУ  │ │
        │ └──┬──┘    └────┬───┘ │
        └─────┼────────────────┼──────┘
              │ шины (адрес/данные/упр)
    ┌──────────┴───────┐  ┌────┴─────────┐
    │ Память (ОЗУ)  │  │ Устройства  │
    │ команды + данные │  │ ввода-вывода │
    └──────────────────┘  └──────────────┘
```

- **Виды архитектур ЭВМ:** централизованная, магистральная, иерархическая (с канальными процессорами); по организации памяти ЦУ — **фон-неймановская/принстонская** (общая память команд и данных) vs **гарвардская** (раздельные памяти и шины — быстрее, в DSP/МК).

## 6. Функциональные блоки ЦП (схема и назначение АЛУ, схема и назначение УУ, основные регистры ЦП).
*Нужны **схема АЛУ** и **схема УУ**.*
- **АЛУ (арифметико-логическое устройство)** — выполняет арифметические и логические операции над операндами; синхронизировано с остальными узлами.

```
  операнд A ─►┌───────────┐
  операнд B ─►│  АЛУ  │─► результат
  код опер. ─►│ (+ − И ИЛИ│
              │ сдвиги) │─► флаги (Z, C, S, O)
              └───────────┘
```

- **УУ (устройство управления)** — формирует управляющие сигналы, дешифрирует команды, задаёт последовательность работы узлов.

```
  команда ─►┌──────────┐─► управляющие сигналы на АЛУ,
  такты  ─►│  УУ   │  регистры, память, ВВ
            │(дешифратор│
            │ + автомат)│
            └──────────┘
```

- **Два типа УУ:**
  - с **жёсткой (схемной)** логикой — быстрое, под конкретную систему команд (→ RISC);
  - **микропрограммное** — гибкое (перенастройка заменой микропрограммы), но медленнее (→ CISC).
- **Основные регистры ЦП:**
  - **PC (Program Counter)** / счётчик команд — адрес следующей команды.
  - **IR (Instruction Register)** — текущая выполняемая команда.
  - **MAR (Memory Address Register)** — адрес ячейки памяти для обращения.
  - **MDR/MBR (Memory Data Register)** — данные, читаемые/пишемые в память.
  - **Аккумулятор**, регистры общего назначения (РОН), регистр флагов.

## 7. Командный цикл процессора, регистр флагов и состояния (понятия команды, потока управления и исполнительного адреса, описание командного цикла, описание флагов в регистре флагов и состояний).
- **Команда** — элементарное действие процессора (код операции + операнды/адреса).
- **Поток управления** — порядок выполнения команд (определяется PC и переходами).
- **Исполнительный адрес** — фактический адрес операнда в памяти (после применения адресации).
- **Командный цикл (7 шагов):**
  1. **Чтение команды:** `IR ← [PC]` (адрес берётся из счётчика команд).
  2. **Увеличение счётчика команд** на 1: `PC ← PC + 1`.
  3. **Формирование адреса операндов** (по виду адресации).
  4. **Извлечение операндов** из памяти/регистров.
  5. **Выполнение** операции в АЛУ.
  6. **Размещение результата** в памяти/регистрах.
  7. **Переход к п. 1** (с проверкой прерываний).
  *(Декодирование командой УУ — между шагами 1 и 3. Не «склеивай» шаги: на схеме их именно 7.)*
- Если вопрос привязан к лабам на **AVR (ATmega)** — там регистр флагов называется **SREG** (биты C, Z, N, V, S, H, T, I), а не EFLAGS.
- **Регистр флагов (FLAGS/EFLAGS)** — биты состояния после операции:
  - **ZF** — нуль (результат = 0); **CF** — перенос/заём; **SF** — знак (старший бит); **OF** — переполнение; **PF** — чётность; **AF** — вспомогательный перенос.
  - Управляющие флаги: **IF** (разрешение прерываний), **DF** (направление), **TF** (трассировка).

## 8. Основные архитектуры системы команд (описание стековой, аккумуляторной, регистровой архитектуры системы команд и архитектура с выделенным доступом к памяти).
- **Система команд** — полный перечень команд, которые способна выполнять машина. **Архитектура системы команд (АСК)** — совокупность средств, **видимых и доступных программисту**. Характеристики АСК: вид/формат данных, место хранения данных, методы доступа, операции над данными, число операндов, способ определения адреса следующей команды, способ кодирования.
- Хронология АСК: аккумуляторная (1950) → стековая (1963–66) → регистровая (1964) → с выделенным доступом к памяти → CISC (1977–80) → RISC (1987) → VLIW (конец 1990-х) → ROSC (безоперандная, 2001).
- **Архитектуры (по способу хранения операндов):**
  - **Стековая** — операнды берутся с вершины стека, безадресные команды. Просто, но медленно (всё через стек).
  - **Аккумуляторная** — один операнд в аккумуляторе, второй в памяти; результат в аккумулятор. Короткие команды, но много обращений к памяти.
  - **Регистровая** — операнды в регистрах общего назначения (РОН). Быстро, основа RISC. Подвиды: регистр-регистр и регистр-память.
  - **С выделенным доступом к памяти (load/store)** — с памятью работают только команды `load`/`store`, арифметика только над регистрами. Чистая RISC-модель.


## 9. Основы построения CISC-, RISC- и VLIW-архитектур системы команд (принципы построения основных архитектур, схема процессора, сравнение функций устройства управления в CISC и RISC процессорах).
*Нужна **схема процессора** и **сравнение УУ в CISC и RISC**.*
- **CISC (Complex Instruction Set)** — много сложных команд разной длины, развитая адресация, команда может делать несколько действий. УУ **микропрограммное** (сложное, медленное). Пример: x86.
- **RISC (Reduced Instruction Set)** — мало простых команд фиксированной длины, выполнение за 1 такт, много регистров, load/store. УУ **аппаратное (схемное)** — быстрое. Конвейеризация. Пример: ARM, MIPS.
- **VLIW (Very Long Instruction Word)** — в одной длинной команде несколько операций, распараллеливание задаёт **компилятор** (не процессор). Простое железо, сложный компилятор. Пример: Itanium, Эльбрус.

```
CISC: команда ─► микропрограммное УУ ─► микрокоманды ─► АЛУ
RISC: команда ─► аппаратное УУ ───────────────────────► АЛУ (1 такт)
```

| | CISC | RISC |
|--|------|------|
| УУ | микропрограммное | аппаратное (схемное) |
| Команды | сложные, переменной длины | простые, фиксированной длины |
| Такты на команду | много | ~1 (конвейер) |
| Регистры | мало | много |
| Доступ к памяти | любая команда | только load/store |

## 10. Форматы команд и виды адресации (классификация команд процессора, примеры форматов команд x86, RISC-16, AVR).
- **Классификация команд:** пересылки (load/store, mov), арифметико-логические, передачи управления (переходы, вызовы), ввода-вывода, системные.
- **Формат команды** = код операции (КОП) + адресная часть. Число адресов: 0 (стек), 1 (аккумулятор), 2–3 (регистровые). Примеры: **x86** — переменная длина; **RISC-16 / AVR** — фиксированная.
- **Виды адресации:**
  - **Прямая** — в команде сам адрес операнда.
  - **Непосредственная** — операнд прямо в команде (константа).
  - **Регистровая** — операнд в регистре.
  - **Косвенная** — в команде адрес ячейки/регистра, где лежит адрес операнда.
  - **Со смещением (базовая/индексная)** — адрес = базовый регистр + смещение.
  - **Относительная** — адрес = PC + смещение (для переходов).

## 11. Понятия конвейерной, суперскалярной и векторной обработки (схема работы конвейера, показатели эффективности конвейера, схема суперскалярного ЦП, конфликты в конвейере, назначение MMX, 3DNow!, SSE, SSE2,…).
*Нужны **схема конвейера** и **схема суперскалярного ЦП**.*
- **Конвейер (pipeline)** — команда делится на ступени (стадии), которые выполняются параллельно для разных команд. Идеально: 1 команда/такт.

```
такт:  1  2  3  4  5  6
К1:   [IF][ID][EX][MEM][WB]
К2:     [IF][ID][EX][MEM][WB]
К3:        [IF][ID][EX][MEM][WB]
        IF=выборка ID=декод EX=исполн MEM=память WB=запись
```

- **Показатели эффективности** (N команд, K ступеней, T_K — такт):
  - **ускорение** `S = NK/(K+N−1) → K`;
  - **эффективность** `E = S/K = N/(K+N−1) → 1`;
  - **производительность** `P = N/(T_K·(K+N−1)) → 1/T_K = F` (частота).
- **Конфликты (hazards) в конвейере:**
  - **Структурные** — нехватка аппаратного ресурса.
  - **По данным** — команда ждёт результат предыдущей (решают форвардингом/простоем).
  - **По управлению** — переход меняет PC (решают предсказанием переходов).
- **Суперскалярный ЦП** — несколько конвейеров/исполнительных устройств → >1 команды за такт (внеочередное исполнение).

```
        ┌─►[ALU 1]─┐
выборка─┤ [ALU 2] ├─► общий результат
неск.  └─►[FPU] ─┘  (>1 команды/такт)
команд
```

- **Векторная обработка** — одна команда над массивом данных (SIMD). Мультимедийные расширения: **MMX** (целые), **3DNow!** (AMD, float), **SSE/SSE2/AVX** (float, расширение регистров).

## 12. Технологии динамического исполнения (краткое описание средств динамического исполнения, технология многократного декодирование команд).
- **Динамическое исполнение** — процессор сам меняет порядок и условия выполнения команд для загрузки конвейера. Средства:
  - **Предсказание переходов (branch prediction)** — угадывает направление ветвления, заранее грузит команды.
  - **Спекулятивное (упреждающее) исполнение** — выполняет команды до того, как известно, нужны ли они; результат отбрасывается, если предсказание неверно.
  - **Внеочередное исполнение (out-of-order)** — команды исполняются по готовности данных, а не по порядку.
  - **Переименование регистров** — устраняет ложные зависимости по регистрам.
- **Многократное (множественное) декодирование команд** — несколько декодеров параллельно разбирают команды, преобразуя сложные CISC-команды в простые микрооперации (μops) для конвейера.

## 13. Основы микроархитектур процессоров (понятие микроархитектуры, технологические нормы, производительность, эксплуатационные характеристики МП, физические параметры МП, общая структура МП).
- **Микроархитектура** — аппаратная организация и логическая структура микропроцессора: регистры, управляющие схемы, АЛУ, запоминающие устройства, информационные магистрали. Противопоставляется **макроархитектуре** = система команд, типы данных, режимы адресации, принципы работы МП.
- **Технологический процесс (техпроцесс/нормы)** — размер элементов на кристалле (нм). Чем меньше, тем больше транзисторов и ниже энергопотребление.
- **Степень интеграции** — число элементов на кристалле.
- **Производительность:** тактовая частота ядра, частота системной шины, объём кэша (L1/L2/L3).
- **Эксплуатационные характеристики:** напряжение питания, потребляемая мощность, тепловыделение (TDP), макс. температура.
- **Физические параметры:** тип и размер корпуса, размер кристалла, число и форма выводов.
- **Общая структура МП:** ядро (АЛУ, регистры, кэш L1/L2) + контроллер памяти + шина/интерконнект между ядрами + периферийные блоки (графика, контроллеры ВВ).

## 14. Микроархитектуры процессоров Intel (перечень поколений и характерные черты микропроцессоров, схема и характеристики какого-нибудь из последних МП).
*Нужна **схема и характеристики одного из последних МП**. Важна хронология + современные особенности.*
- **Хронология (поколения):** 4004 (1971, 4-бит) → 8086 (16-бит, x86) → 80286 (защищённый режим) → 80386 (32-бит) → 80486 (кэш на кристалле) → **Pentium** (суперскаляр) → Pentium Pro/II/III (out-of-order, MMX/SSE) → **Pentium 4** (NetBurst, длинный конвейер, Hyper-Threading) → **Core** (многоядерность, отказ от длинного конвейера) → Core i3/i5/i7/i9 (Nehalem→…→современные).
- **Современные особенности Intel:**
  - **Гибридная архитектура** (с Alder Lake): **P-ядра** (Performance) + **E-ядра** (Efficiency), планировщик **Thread Director**.
  - Интегрированный контроллер памяти и графика, кэш L1/L2/L3, кольцевая/mesh-шина между ядрами.
  - Технологии: Hyper-Threading (SMT), Turbo Boost, AVX-512.
- **Схема современного МП (обобщённо):**

```
┌─────────────────────────────────────────┐
│ P-ядро P-ядро E-ядро E-ядро iGPU   │
│  │L1/L2 │L1/L2 └──┬──┘         │
│  └───────┴── общий кэш L3 (кольцо/mesh) │
│  Контроллер памяти │ Контроллер PCIe  │
└─────────────────────────────────────────┘
```

## 15. Микроархитектуры процессоров AMD (перечень поколения и характерные черты микропроцессоров, схема и характеристики какого-нибудь из последних МП).
*Нужна **схема и характеристики одного из последних МП**.*
- **Хронология:** Am286/386/486 (клоны Intel) → **K5** (первая своя архитектура) → **K6** (MMX, 3DNow!) → **Athlon (K7)** — аналог/конкурент Pentium III → **Athlon 64 / Opteron (K8)** — первым ввёл **64-бит (AMD64/x86-64)**, встроенный контроллер памяти, шина **HyperTransport** → **Opteron/Phenom (K10)** — 4 ядра на кристалле → Bulldozer (модульная) → **Zen/Zen2/3/4/5** — современная (чиплеты).
- **Современные особенности AMD (Ryzen, Zen):**
  - **Чиплетная компоновка** — несколько кристаллов **CCD** (ядра) + **I/O-die**, связь по шине **Infinity Fabric**. Дешевле в производстве, лучше выход годных.
  - Большой L3-кэш (**3D V-Cache** — кэш «этажом» над ядрами), SMT, поддержка PCIe.
- **Особенности/отличия от Intel:**
  - раньше внедрили 64-бит и встроенный контроллер памяти;
  - чиплеты (у AMD) против монолита (у Intel); гибрид P+E у Intel — у AMD ядра однотипные;
  - Infinity Fabric против кольцевой/mesh-шины.

```
┌──────────────────────────────────┐
│ CCD0 (8 ядер + L3) CCD1 (8 ядер) │
│    └──── Infinity Fabric ─────┤
│       I/O-die       │
│  (контроллер памяти, PCIe, USB) │
└──────────────────────────────────┘
```

## 16. Основы построения компьютерной памяти (методы доступа к данным, характеристики памяти, иерархическая организация памяти, обнаружение и исправление ошибок).
- **Виды ЗУ:** **процессорные** (регистры, кэш L1/L2/L3) · **внутренние** (основная память — ЦП обращается напрямую) · **внешние** (большой ёмкости, подключаются как ВВ — диски, ленты).
- **Методы доступа:** последовательный (лента), прямой (диск), произвольный (ОЗУ — любая ячейка за одно время), ассоциативный (по содержимому, параллельно — кэш).
- **Характеристики:**
  - ёмкость;
  - быстродействие: **время доступа** (от выдачи адреса до готовности данных), **длительность цикла / период обращения** (мин. интервал между двумя обращениями), **скорость передачи**;
  - удельная стоимость;
  - энергозависимость.
- **Иерархия памяти** (основана на **принципе локальности** обращений; сверху вниз: быстрее+дороже+меньше → медленнее+дешевле+больше):

```
регистры → L1-кэш → L2-кэш (→ L3) → ОЗУ → дисковая кэш-память → магнитные диски / RAID → оптические диски, ленты
```

взаимодействуют только два соседних уровня; **попадание (hit)** / **промах (miss)**, hit rate.
- **Обнаружение и исправление ошибок:** **отказ** (постоянный — дефект/износ, разряд всегда 0 или 1) vs **сбой** (случайный, без дефекта). Основа — **корректирующие коды** (избыточность): **бит чётности** обнаруживает 1 ошибку; **код Хэмминга / ECC** обнаруживает 2 и исправляет 1.


## 17. Основная память, статические ОЗУ (структура ОП, характеристики, блочная организация ОП, запоминающий элемент в статическом ОЗУ, виды статических ОЗУ).
*Нужен **запоминающий элемент SRAM**.*
- **Структура ОП:** массив ячеек с адресами, дешифратор адреса, регистры данных, схемы чтения/записи. **Блочная организация** — память делится на банки для параллельного доступа.
- **Характеристики:** объём, разрядность, время доступа, цикл обращения.
- **Запоминающий элемент SRAM** — **триггер на 4–6 транзисторах**. Хранит бит, пока есть питание, регенерация не нужна. Быстрый, но дорогой и малой плотности → используется для **кэша**.
- **Виды SRAM (4 группы):** **асинхронные** (низко-/средне-/высокоскоростные), **синхронные** (с чередованием адресов, конвейерные, ZBT, DDR, двухпортовые), **специального применения** (многопортовые, FIFO, теговое ЗУ кэша), **энергонезависимые** (NVRAM, BBSRAM).

## 18. Динамические ОЗУ (виды динамических ОЗУ, запоминающий элемент, методы ускорения микросхемы, способы регенерации данных).
*Нужен **запоминающий элемент DRAM**.*
- **Запоминающий элемент DRAM** — **1 транзистор + 1 конденсатор**. Бит = заряд конденсатора. Дёшево, высокая плотность → основная память. Минус: заряд утекает → нужна **регенерация**.
- **Виды ДОЗУ:** **асинхронные** (FPM, EDO, BEDO) и **синхронные** (SDRAM, DDR/DDR2/3/4/5, RDRAM).
- **Способы регенерации (3):** **ROR** (RAS Only Refresh — построчно), **CBR** (CAS before RAS — по внутреннему счётчику строк), **Self-Refresh** (авторегенерация в режиме энергосбережения).
- **Методы ускорения ядра:** быстрый постраничный, пакетный, конвейерный, удвоение скорости (DDR — передача по обоим фронтам такта).

## 19. Специальные типы оперативной памяти, ПЗУ (виды энергонезависимых ОЗУ, виды ПЗУ: EEPROM, Flash, ОЗУ для видеоадаптеров, стековая память).
- **Виды энергонезависимых ОЗУ:** **NVRAM**, **BBSRAM** — статическое ОЗУ с резервным питанием (батарейкой).
- **Виды ПЗУ:**
  - **ROM (масочное)** — прошивается на заводе, не меняется.
  - **PROM** — однократно программируемое.
  - **EPROM** — стирается УФ-светом, перепрограммируемое.
  - **EEPROM** — стирается электрически, побайтно.
  - **Flash** — электрически, блоками; высокая плотность (SSD, BIOS). Две технологии: **NOR** (быстрый доступ к каждой ячейке, память программ микроконтроллеров) и **NAND** (выше плотность, доступ группами — SSD, USB-флешки). Плотность хранения: **SLC** (1 бит/ячейку), **MLC** (2), **TLC** (3).
  - **PCM** (Phase Change Memory) — фазовая память (перепрограммируемое ПЗУ).
- **ОЗУ для видеоадаптеров:** **VRAM** (двухпортовая — одновременно вывод на экран и запись), SGRAM, GDDR.
- **Стековая память** — LIFO, для адресов возврата и локальных данных.


## 20. Организация кэш-памяти, способы отображения основной памяти на кэш-память (назначение кэш-памяти, уровни кэш-памяти, факторы эффективности кэш-памяти, схемы вариантов отображения ОП на кэш-память и сравнение).
*Нужны **схемы вариантов отображения**.*
- **Назначение кэша** — быстрая буферная память между ЦП и ОП, хранит часто используемые данные (принцип локальности: временна́я и пространственная).
- **Уровни:** L1 (в ядре, самый быстрый, раздельный для команд/данных), L2, L3 (общий для ядер).
- **Факторы эффективности:** объём, скорость, процент попаданий (hit rate), стратегия отображения и замещения.
- **Способы отображения ОП на кэш:**
  - **Прямое (direct-mapped)** — блок ОП → строго в одну строку кэша (`№ = адрес mod N`). Просто и быстро, но частые вытеснения (конфликты).
  - **Полностью ассоциативное** — блок → в любую строку. Гибко, нет конфликтов, но дорогой поиск (сравнение всех тегов).
  - **Множественно-ассоциативное (set-associative)** — кэш делится на наборы по K строк; блок → в любую строку своего набора. **Компромисс**, применяется на практике (2-, 4-, 8-way).

```
Прямое:    блок ОП ──► 1 строка (адрес mod N)
Ассоциативное: блок ОП ──► любая строка
Множ.-ассоц.: блок ОП ──► любая строка набора (K-way)
```

## 21. Порядок замещения строк в кэш-памяти, согласование ОП и кэш-памяти, дисковая кэш-память (перечень алгоритмов выбора замещаемой строки, краткое описание алгоритмов согласование содержимого ОП и кэш-памяти для однопроцессорных ЭВМ, характеристики дисковой кэш-памяти).
- **Алгоритмы замещения строки:**
  - **LRU** (Least Recently Used) — вытесняем дольше всех неиспользуемую.
  - **LFU** (Least Frequently Used) — реже всех используемую.
  - **FIFO** — первую вошедшую.
  - **Random** — случайную.
  - **ARC** (Adaptive Replacement Cache) — комбинирует LRU+LFU (патент IBM).
- **Алгоритмы согласования ОП↔кэш (однопроцессорные ЭВМ):**
  - **Сквозная запись (write-through)** — сразу в кэш и в ОП. Просто, но медленно.
  - **Простой свопинг** — обратная запись блока в ОП при его вытеснении.
  - **Свопинг с флагами** — в ОП переписывается только при установленном бите модификации (dirty). Быстрее.
  - **Регистровый свопинг с флагами** — то же с буферным регистром для ускорения.
- **Дисковый кэш** — буфер в ОЗУ для часто запрашиваемых секторов диска; ускоряет дисковый ввод-вывод.

## 22. Организация защиты памяти (назначение средств защиты памяти, краткое описание методов защиты памяти).
- **Назначение:** не дать программе обратиться к чужой/системной памяти (изоляция, надёжность, безопасность).
- **Методы (4):**
  - **Защита отдельных ячеек** — «разряд защиты» в ячейке запрещает запись в неё (для отладки программ).
  - **Граничные регистры** — задают нижнюю и верхнюю границу области процесса.
  - **Ключи защиты** — каждому блоку памяти и программе присвоен ключ; доступ при совпадении.
  - **Кольца защиты (уровни привилегий 0–3)** — режим ядра vs пользователя; для страниц — биты доступа R/W/X.

## 23. Концепция виртуальной памяти (схемы страничного, сегментного и сегментно-страничного распределения виртуальной памяти, страничная таблица, TLB).
*Нужны **схемы страничного, сегментного, сегментно-страничного** распределения.*
- **Виртуальная память** — механизм: программа работает в логическом (виртуальном) адресном пространстве больше физического; трансляция вирт.→физ. адреса аппаратно (MMU), редко используемое выгружается на диск (swap).
- **Страничное** — память делится на страницы фиксированного размера. Вирт. адрес = № страницы + смещение → через **страничную таблицу** в физ. адрес.
- **Сегментное** — деление на сегменты переменной длины (по смыслу: код, данные, стек). Адрес = № сегмента + смещение.
- **Сегментно-страничное** — комбинация: сегменты делятся на страницы (x86). Гибкость сегментов + удобство страниц.
- **Страничная таблица** — поля записи: **V** (присутствие страницы в ОП; V=0 → **страничный сбой / page fault**), **R** (использование — для замещения), **M** (модификация — для свопинга с флагами), **A** (права доступа: чтение/запись). Сокращение длины таблицы: многоуровневые таблицы, инвертированная таблица.
- Характеристики: **страничная** → внутренняя фрагментация; **сегментная** → внешняя фрагментация, но удобен разделяемый доступ к общим сегментам.
- **TLB (Translation Lookaside Buffer)** — кэш недавних трансляций адресов (8–4096 записей, полностью/множественно-ассоциативный), ускоряет MMU (без него — лишнее обращение к таблице на каждый доступ).

```
вирт. адрес ─► [TLB?] ─есть─► физ. адрес
                  └─нет─► страничная таблица ─► физ. адрес (+ занести в TLB)
```

## 24. Организация НЖМД, SSD, оптической памяти, магнитных лент (характеристики дисковой памяти, принципы организации SSD-памяти, принципы организации оптической памяти, назначение магнитных лент).
- **НЖМД (HDD)** — магнитные пластины, головки. Геометрия: **дорожки, секторы, цилиндры**. Характеристики: ёмкость, скорость вращения (об/мин), время доступа (seek), интерфейс. Дёшево за ГБ, но механика — медленно.
- **SSD** — флеш-память (NAND), нет механики. Быстрее, тише, надёжнее к ударам. Минус: ограниченный ресурс перезаписи ячеек → **контроллер с wear-leveling** (равномерный износ), TRIM. Чем больше параллельных каналов NAND, тем быстрее.
- **Оптика (CD/DVD/Blu-ray)** — данные = питы/лэнды на дорожке, читаются лазером. Спиральная дорожка от центра.
- **Магнитные ленты** — последовательный доступ, огромная ёмкость, дёшево → **архивное резервное копирование**.

## 25. Избыточные дисковые подсистемы (назначение, способы повышения производительности ЗУ, способы повышения надёжности ЗУ, схемы уровней RAID-массивов).
*Нужны **схемы уровней RAID**.*
- **Назначение RAID** — объединить диски для роста производительности и/или надёжности.
- **Производительность** — **расслоение (stripe)**: данные параллельно на несколько дисков.
- **Надёжность (3 способа):** **зеркалирование (mirror)** — избыточность 100%; **код Хэмминга** — ~30%; **контроль чётности (parity)** — ~20%.
- **Уровни:**
  - **RAID 0** — striping, без избыточности. Быстро, но смерть 1 диска = потеря всего.
  - **RAID 1** — mirroring (зеркало). Надёжно, но 50% ёмкости.
  - **RAID 5** — striping + чётность по всем дискам. Переживает отказ 1 диска. Баланс.
  - **RAID 6** — две чётности, переживает 2 диска.
  - **RAID 10 (1+0)** — зеркало + страйп. Скорость и надёжность, дорого.

```
RAID0: A1 A2 | A3 A4   (скорость)
RAID1: A1 A1 | A2 A2   (зеркало)
RAID5: A1 A2 Ap | A3 Ap A4 (данные+чётность распределены)
```

## 26. Основы построения компьютерных шин (типы шин, иерархия шин, ША, ШД, ШУ, состав линий в ШУ).
- **Шина (bus)** — набор линий для обмена между функциональными блоками (ЦП↔память, ЦП↔ВВ, память↔ВВ); «двунаправленный универсальный коммутатор».
- **Функциональные типы:**
  - **ША (адреса)** — **однонаправленная**, разрядность задаёт объём адресуемой памяти (`N=2ⁱ`);
  - **ШД (данных)** — **двунаправленная**, последовательная или параллельная, ширина = слово;
  - **ШУ (управления)** — линии управляющей информации и состояния.
- **Иерархия шин:** системная (ЦП–память) → шина расширения → шина ввода/вывода (через адаптеры); архитектура с «пристройкой» (mezzanine). Чем ближе к ЦП, тем быстрее.
- **Состав линий ШУ (7 групп):** сигналы управления транзакциями (тип операции, кол-во передаваемых байт, тип адреса, тип протокола), информация состояния (статуса), арбитраж, прерывания, последовательные локальные сети, позиционный код, тактирование и синхронизация.

## 27. Организация арбитража шины (схемы приоритетов, схемы арбитража, способы организации опроса).
*Нужны **схемы приоритетов и арбитража**.*
- **Арбитраж** — процедура допуска к управлению шиной только одного из ведущих (master). **Арбитр** распределяет доступ (обычно на северном мосту).
- **Схемы приоритетов:** **статические** (фиксированные) и **динамические**. Динамические алгоритмы: простая циклическая смена, циклическая с учётом последнего запроса, по случайному закону, равных приоритетов, LRU (наиболее давнее использование).
- **Схемы арбитража:**
  - **Централизованная** (один арбитр):
    - **параллельная** — у каждого ведущего своя линия запроса/предоставления;
    - **последовательная (цепочечная, daisy chain)** — сигнал разрешения идёт по цепочке, ближний к арбитру = высший приоритет.
  - **Децентрализованная (распределённая)** — единого арбитра нет, у каждого ведущего свой контроллер шины.
- **Способы организации опроса:** **централизованный** (контроллер по очереди опрашивает ведущих, выставляя их адрес) и **децентрализованный** (каждый ведущий сам формирует адрес следующего).


## 28. Типы протоколов шин, синхронная и асинхронная передача данных (управление процессом передачи данных, схемы и принципы работы протоколов шин).
*Нужны **схемы протоколов**.*
- **Синхронная передача** — общий тактовый сигнал, события привязаны к фронтам такта. Быстро и просто, но все устройства на одной частоте, длина ограничена.
- **Асинхронная передача** — без общего такта, по **квитированию (handshake)**: запрос → готовность (request/acknowledge). Гибко (разные скорости устройств), но медленнее и сложнее.

```
Синхронная: CLK ‾|_|‾|_|‾|_  данные привязаны к фронтам
Асинхронная: REQ ──► устройство ──► ACK (рукопожатие)
```

## 29. Методы повышения эффективности шин, надёжность и отказоустойчивость шины (способы повышения эффективности шин, способы повышения надёжности шин).
- **Повышение эффективности (полосы):** **отказ от мультиплексирования** ША/ШД, увеличение ширины ШД и тактовой частоты, **блочные/пакетные транзакции (burst)**, **конвейеризация** и **расщепление транзакций (split)**, арбитраж с перекрытием и с удержанием шины, переход на **последовательные дифференциальные** линии (PCIe вместо PCI).
- **Повышение надёжности:** контроль чётности/ECC на шине, дублирование/резервные линии, экранирование, протоколы повтора при ошибке.

## 30. Внутренние интерфейсы ЭВМ: EISA, LPC, PCI, PCI-E, AGP (основные характеристики).
- **EISA** — расширение ISA, 32-бит, для серверов (устаревший).
- **LPC (Low Pin Count)** — для низкоскоростной периферии (контроллеры клавиатуры, BIOS), заменил ISA.
- **PCI** — параллельная, 32/64-бит, 33/66 МГц, общая шина с арбитражем (устаревает).
- **PCI-E (PCI Express)** — **последовательная**, по «линиям» (lanes ×1…×16), независимые дифференциальные пары, point-to-point. Современный стандарт.
- **AGP** — выделенный интерфейс для видеокарт (между PCI и PCI-E исторически), вытеснен PCI-E.

## 31. Внешние интерфейсы для ЗУ: IDE, SATA, SCSI, SAS (основные характеристики).
- **IDE/PATA** — параллельный, для HDD/CD, шлейф 40/80 жил, 1–2 устройства, до 45 см (устарел).
- **SATA** — **последовательный** наследник IDE, точка-точка, hot-swap. Ревизии: **1.0 — 1.5 Гбит/с, 2.0 — 3, 3.0 — 6 Гбит/с**; SATA Express (PCIe). Массовый для дисков.
- **SCSI** — **параллельный**, шина для нескольких устройств, для серверов (очередь команд). От обычного SCSI (8 бит, 5 МБ/с) до **Ultra-640 (16 бит, 640 МБ/с)**.
- **SAS (Serial Attached SCSI)** — **последовательный** наследник SCSI: точка-точка, **полнодуплекс**, **1.5/3/6/12 Гбит/с** на линию, до **16 384** устройств, обратно совместим с SATA. Компоненты: инициаторы, целевые устройства, подсистема доставки, расширители.

## 32. Внешние интерфейсы для ввода/вывода: RS-232C, LPT (EPP, ECP), USB, SPI, I²C (основные характеристики).
- **RS-232C** — последовательный COM-порт, низкая скорость, для модемов/терминалов (устарел).
- **LPT** — параллельный порт для принтеров; режимы **EPP** (двунаправленный) и **ECP** (с DMA и сжатием).
- **USB** — последовательный, универсальный, hot-plug, питание, до USB4 (40 Гбит/с), топология «дерево» с хабами.
- **SPI** — синхронный, 4 линии (MOSI/MISO/SCLK/CS), быстрый, для микросхем на плате, full-duplex.
- **I²C** — синхронный, **2 линии** (SDA/SCL), адресация устройств, медленнее SPI, для датчиков.

## 33. Система ввода-вывода, организация адресного пространства (способы подключения СВВ к ЦП и ОП, достоинства и недостатки совмещённого и выделенного адресного пространства).
- **Способы подключения СВВ:**
  - **Совмещённое адресное пространство (memory-mapped I/O)** — порты ВВ в общем адресном пространстве с памятью. Плюс: любые команды работы с памятью годятся для ВВ. Минус: «съедает» адреса памяти.
  - **Выделенное адресное пространство (port-mapped, x86 `IN`/`OUT`)** — отдельное пространство портов. Плюс: не отнимает память, отдельные команды. Минус: нужны спец. команды, сложнее.

## 34. Модуль ввода/вывода, абстрактное периферийное устройство (структура и функции МВВ, схема ПУ).
*Нужна **схема ПУ**.*
- **МВВ (модуль ввода-вывода)** — посредник между системной шиной и периферией. **5 функций:** локализация данных (дешифрация адреса ВУ/регистра, адресация данных на ПУ), управление и синхронизация, обмен информацией, буферизация (согласование скоростей ЦП и ПУ), обнаружение ошибок.
- **Структура МВВ:** регистры данных, регистры состояния/управления, дешифратор адреса, логика управления, интерфейс с ПУ.

```
системная  ┌─────────────┐  ┌──────────┐
шина ◄─────►│  МВВ    │◄─►│  ПУ   │
            │ рег.данных  │  │(датчик/ │
            │ рег.состояния│  │ привод) │
            │ упр.логика  │  └──────────┘
            └─────────────┘
```

## 35. Программно-управляемый ввод/вывод, ввод/вывод по прерываниям (блок-схемы обоих способов, принцип работы векторных прерываний).
*Нужны **блок-схемы обоих способов**.*
- **Программно-управляемый (polling)** — ЦП в цикле опрашивает флаг готовности ПУ. Просто, но ЦП впустую крутит цикл ожидания.

```
[читать рег.состояния]→[готов?]──нет──┐ (цикл ожидания)
                          │да     │
                          ▼      └──────┘
                    [обмен данными]
```

- **ВВ по прерываниям** — ПУ само сигналит прерыванием, когда готово; ЦП занят своим делом, по сигналу переключается на обработчик. Эффективнее.
- **Векторное прерывание** — ПУ передаёт **номер (вектор)**, по нему ЦП находит адрес обработчика в таблице векторов.

```
ЦП работает… ──[IRQ от ПУ]──► сохранить состояние ─►
обработчик (по вектору) ─► обмен ─► вернуться
```

## 36. Прямой доступ к памяти (схема подключения КПДП, способы распределения системной шины между ЦП и КПДП, примеры схем конфигураций систем ПДП).
*Нужна **схема КПДП** и **конфигурации**.*
- **ПДП (DMA)** — обмен ПУ↔память **без участия ЦП**, через контроллер **КПДП (DMAC)**. ЦП освобождается, эффективно для больших блоков.
- **Способы распределения шины между ЦП и КПДП:**
  - **С захватом цикла (cycle stealing)** — КПДП «крадёт» отдельные циклы шины.
  - **Блочный (burst)** — КПДП захватывает шину на весь блок.
  - **Прозрачный** — КПДП работает, когда ЦП не использует шину.

```
        ┌─────┐ запрос DMA ┌──────┐
ЦП ◄──►│КПДП │◄──────────►│ ПУ │
        └──┬──┘      └──────┘
          ▼ (шина)
        [ Память ]  ← обмен ПУ↔память минуя ЦП
```

## 37. Каналы и процессоры ввода/вывода (принципы работы, схема, управляющие слова канала, БУВУ).
- **Назначение** — разгрузить ЦП: канал = специализированный процессор ВВ, выполняет **канальную программу** (управляющие слова канала, УСК).
- **Режимы работы канала:**
  - **Мультиплексный** — несколько ВУ разделяют канал во времени (много медленных устройств, короткими сеансами; байт-/блок-мультиплексный).
  - **Монопольный** — одно (быстрое) ВУ монополизирует канал до завершения канальной программы (диски).
- **БУВУ (блок управления внешними устройствами)** — управляет конкретным ПУ под командой канала.

## 38. Организации системы прерываний. (способы организации системы прерываний, виды прерываний, аппаратные и программные средства системы прерываний).
- **Прерывание** — приостановка текущей программы для реакции на событие, с переходом на обработчик и возвратом.
- **Виды прерываний:**
  - **Аппаратные внешние** — от устройств (IRQ).
  - **Внутренние (исключения)** — ошибки ЦП. Три типа: **отказ (fault)** — обнаруживается до инструкции, после обработки возврат на **ту же** инструкцию (отказ страницы #PF, деление на 0 #DE); **ловушка (trap)** — после инструкции, возврат на **следующую** (#BP, #OF); **аварийное завершение (abort)** — нельзя точно установить инструкцию (#DF двойной отказ).
  - **Программные** — команда `INT n` (системные вызовы).
- Внешние делятся на **немаскируемые (NMI)** и **маскируемые (INTR)** (маскируются флагом IF).
- **Способы организации:** опрос (polling), векторные прерывания, приоритеты.
- **Средства:** аппаратные — выводы ЦП (INTR/NMI/INTA), **контроллер прерываний (8259A / APIC)** для приоритезации и маскирования; программные — таблица векторов, флаги IF/TF, команды `int/iret/cli/sti`.


## 39. Прерываний в реальном и защищённом режимах, защита в процедурах прерываний (таблицы векторов прерываний, шлюзы прерываний, алгоритмы выполнения прерываний, средства защиты в процедурах прерываний).
- **Реальный режим** — **таблица векторов прерываний (IVT)** в начале памяти, каждый вектор = адрес обработчика (CS:IP).
- **Защищённый режим** — **IDT (таблица дескрипторов прерываний)** из **шлюзов (gates)**: шлюз прерывания/ловушки/задачи, с проверкой уровня привилегий.
- **Алгоритм:** сигнал → сохранить состояние (флаги, CS:IP) → по вектору найти обработчик → проверка привилегий → выполнить → `IRET`.
- **Защита в процедурах прерываний:** контроль уровня привилегий (кольца), шлюзы ограничивают точки входа в ядро.

## 40. Чипсет ЭВМ (назначение, архитектура «северный мост – южный мост», пример схемы современного чипсета с указанием основных интерфейсов).
*Нужна **схема современного чипсета**.*
- **Чипсет** — набор микросхем на плате, связывающий ЦП, память и периферию.
- **Классическая архитектура «северный мост — южный мост»:**
  - **Северный мост (Northbridge)** — быстрый: контроллер памяти, графика (AGP/PCIe), связь с ЦП.
  - **Южный мост (Southbridge)** — медленная периферия: USB, SATA, PCI, LPC, BIOS, аудио, сеть.
- **Современно:** контроллер памяти и графики **встроены в ЦП**, остался один чип **PCH** (Platform Controller Hub), связь с ЦП по DMI.

```
        ┌─────┐ встроены контроллер памяти + PCIe + iGPU
        │ ЦП │──── PCIe ──► видеокарта
        └──┬──┘
            │ DMI
        ┌──┴──────┐ USB, SATA, сеть, аудио,
        │ PCH  │ LPC→BIOS, PCIe-периферия
        └─────────┘
```

## 41. Подсистема ROM BIOS (назначение, программы POST и CMOS, назначение прерываний, организация стандарта Plug&Play).
- **BIOS (Basic Input Output System)** — прошивка в ПЗУ на плате: базовые драйверы устройств, загрузка ОС.
- **POST (Power-On Self Test)** — самотестирование при включении (память, устройства).
- **CMOS** — энергонезависимая память (с батарейкой) с настройками BIOS (время, параметры).
- **Прерывания BIOS** — программные сервисы доступа к устройствам в реальном режиме.
- **Plug&Play** — автоматическое распознавание и конфигурирование устройств (распределение ресурсов: IRQ, DMA, адреса). Современная замена — **UEFI**.

## 42. Периферийные устройства ввода (клавиатура: принцип работы, оптическая мышь: принцип работы, механические устройства позиционирования: шариковая мышь/трекбол/джойстик, сканеры: принцип работы).
- **Клавиатура** — матрица клавиш, контроллер опрашивает строки/столбцы, выдаёт **скан-код**.
- **Оптическая мышь** — подсветка поверхности + микрокамера + DSP, по смещению картинки считает перемещение.
- **Механические позиционеры:** шариковая мышь (шарик→ролики→датчики), трекбол, джойстик.
- **Сканеры** — оптический датчик (CCD/CIS) построчно считывает отражённый свет, оцифровывает изображение.

## 43. Периферийные устройств вывода (принтеры: принципы работы лазерных и струйных принтеров, звуковая система: схема AC97, графическая система: назначение, дополнительные блоки в акселераторе и сопроцессоре).
*Можно **схема AC97**.*
- **Принтеры:**
  - **Лазерный** — лазер рисует скрытое изображение на барабане (электростатика), тонер прилипает, переносится на бумагу, запекается. Чёткий, быстрый.
  - **Струйный** — печатающая головка распыляет капли чернил. Дёшево, цветная фотопечать.
- **Звуковая система (AC97)** — стандарт: цифровой контроллер на чипсете + аналоговый **кодек AC97** (ЦАП/АЦП). Разделение цифровой и аналоговой частей.
- **Графическая система** — видеоадаптер: видеопамять, кадровый буфер, **RAMDAC + ЦАП**, контроллер ЭЛТ (CRTC), ROM Video BIOS. Дополнительные блоки:
  - **акселератор** — аппаратный курсор, блок продвинутой графики, BitBlt, блок выполнения операций (готовые функции);
  - **сопроцессор** — полноценный процессор: ОЗУ микроинструкций, УУ, АЛУ, регистры (программируемый).

## 44. Уровни и средства комплексирования в ВС, классификация ВС по Флину (понятие гранулярности, уровни параллелизма, уровни комплексирования и принципы взаимодействия, классификация ВС по Флину).
*Нужна **классификация по Флинну** (схема).*
- **Гранулярность** — мера отношения объёма вычислений к объёму коммуникаций (обмена сообщениями). Виды (с указанием, кто обеспечивает): **крупнозернистый** (coarse, тысячи команд, обеспечивает ОС) / **среднезернистый** (medium, сотни команд, программист или компилятор) / **мелкозернистый** (fine, ~10 команд, векторизирующий компилятор). При малой коммуникац. задержке выигрывает мелкозернистое разбиение, при большой — крупнозернистое.
- **Уровни параллелизма (4):** микроуровень (фазы команды перекрыты конвейером) → уровень команд (несколько конвейеров — суперскаляр) → уровень потоков (на параллельных ВС) → уровень заданий (независимые задания на разных процессорах).
- **Уровни комплексирования машин (5):**
  1. прямого управления (процессор–процессор, короткие приказы-сообщения);
  2. общей оперативной памяти (через быстрый коммутатор — лучший для оперативного взаимодействия);
  3. комплексируемых каналов ВВ (адаптер «канал–канал»);
  4. устройств управления внешними устройствами (УВУ, двухканальный переключатель);
  5. общих внешних устройств.
- Доп. классификации (могут спросить): **Джонсона** (для MIMD: GMSV/DMSV/GMMP/DMMP — общая/распределённая память × разделяемые переменные/передача сообщений) и **Скилликорна** (процессоры IP/DP, память IM/DM, переключатели; всего 28 классов).
- **Классификация Флинна** — по числу потоков команд (Instruction) и данных (Data):

| | один поток данных (SD) | много потоков данных (MD) |
|--|--|--|
| **один поток команд (SI)** | **SISD** — обычный фон-Нейман | **SIMD** — векторные, матричные |
| **много потоков команд (MI)** | **MISD** — конвейер/систолич. (редко) | **MIMD** — мультипроцессоры, кластеры |

```
SISD: 1 команда → 1 данные   SIMD: 1 команда → много данных
MISD: много команд → 1 данные  MIMD: много команд → много данных
```

## 45. Метрики параллельных вычислений, закон Амдала (7 метрик с формулами и закон Амдала с выводами).
*Нужны **7 метрик с формулами** и **закон Амдала с выводами**.*

Обозначения: `T(1)=O(1)` — время/объём операций на 1 процессоре; `T(n)`, `O(n)` — время и объём операций на n процессорах.

1. **Степень параллелизма** `P(t)` — число процессоров, одновременно выполняющих программу в момент t (даёт **профиль параллелизма**).
2. **Индекс параллелизма** `PI(n) = O(n) / T(n)` — средняя скорость (операций в единицу времени).
3. **Ускорение** `S(n) = T(1) / T(n)` — во сколько раз быстрее. Идеал `S = n`.
4. **Эффективность** `E(n) = S(n)/n = T(1) / (n·T(n))` — доля ускорения на один процессор (0…1).
5. **Утилизация** `U(n) = O(n) / (n·T(n))` (= R·E).
6. **Избыточность** `R(n) = O(n) / O(1)` — во сколько раз больше операций.
7. **Сжатие** `C(n) = O(1) / O(n)` (величина, обратная избыточности).
8. **Качество** `Q(n) = T³(1) / (n·T²(n)·O(n)) = S·E·C` — обобщённый показатель.

**Пример:** `n=8`, `T(1)=O(1)=O(8)=93`, `T(8)=25` → `S=PI=3.72`; `E=U=0.465`; `R=C=1`; `Q=1.73`.

- **Закон Амдала.** Если доля **последовательного** кода `f` (не распараллеливается), то максимальное ускорение:

```
        S(n) = 1 / (f + (1 − f)/n)
                          ↓ при n → ∞
        S_max = 1 / f
```

- **Вывод:** ускорение ограничено последовательной частью. Если `f = 10%`, то даже на ∞ процессорах `S_max = 10`. **Главный смысл: распараллеливать бесполезно, пока велика последовательная доля** — наращивание процессоров упирается в потолок `1/f`.

## 46. Виды ВС: UMA и NORMA (схемы и принципы работы).
*Нужны **схемы и принципы**.*
- **UMA (Uniform Memory Access)** — общая память, **одинаковое время доступа** для всех процессоров. Связь через общую шину/коммутатор. К UMA относятся **SMP** (симметричная мультипроцессорная) и **PVP** (на векторных процессорах). Минус: шина — узкое место, плохо масштабируется.

```
[ЦП][ЦП][ЦП][ЦП]
    └──общая шина──┘
      [ общая память ]   ← время доступа одинаково
```

- **NORMA (No Remote Memory Access)** — у каждого процессора **только своя локальная память**, чужую напрямую читать нельзя — **только обмен сообщениями** по сети. Это основа **кластеров и MPP**. Хорошо масштабируется.

```
[ЦП+память]──сеть──[ЦП+память]──сеть──[ЦП+память]
    обмен только сообщениями (нет общего адр. пространства)
```

## 47. Виды ВС: NUMA, COMA и DSM (принципы работы, + для NUMA – схема).
*Для **NUMA — схема**.*
- **NUMA (Non-Uniform Memory Access)** — общее адресное пространство, но память **физически распределена**: доступ к своей памяти быстрый (напрямую), к чужой (удалённой) — медленнее (через коммутатор/сеть). Масштабируется лучше UMA. **Подвиды:** **ccNUMA** (cache coherent — с обеспечением когерентности кэшей) и **nccNUMA** (без когерентности).

```
узел0: [ЦП]-[локальная память] ┐
узел1: [ЦП]-[локальная память] ├─ сеть/коммутатор (общее адр. простр.)
узел2: [ЦП]-[локальная память] ┘  своя память — быстро, чужая — медленно
```

- **COMA (Cache Only Memory _Architecture_)** — вся локальная память работает как **большой кэш**; данные мигрируют к процессору, который их использует. Нет фиксированной «домашней» памяти.
- **DSM (Distributed Shared Memory)** — физически распределённая память программно представляется как **общая** (виртуальное общее адр. пространство поверх сети).

## 48. Виды ВС класса SIMD: векторные и матричные (принципы построения, общие схемы работы, + для векторных – классификация).
*Нужны **общие схемы**, для векторных — классификация.*
- **SIMD** — одна команда над множеством данных одновременно.
- **Векторные** — **векторный процессор**: операндами команд могут быть массивы (векторы). **Классификация обработки:** векторно-**параллельная** (несколько конвейерных ФБ параллельно над векторами) и векторно-**конвейерная**.

```
Векторный: вектор A ─►[конвейерное АЛУ]─► вектор C
            вектор B ─►  (поэлементно)
```

- **Матричные** — **массив одинаковых процессорных элементов (ПЭ)**, каждый со своей памятью. **Контроллер массива ПЭ (КМП)** выполняет последовательный код и транслирует команды/данные всем ПЭ по шине широковещательной рассылки; результаты идут по шине результата. **Фронтальная ВМ** загружает программы и данные в КМП. Состав ПЭ: АЛУ, регистры данных, сетевой интерфейс, номер ПЭ, **регистр флага маскирования F**, локальная память (маска отключает часть ПЭ от выполнения команды).

```
        ┌─ общий УУ (одна команда всем) ─┐
        ▼   ▼   ▼   ▼
      [ПЭ]  [ПЭ]  [ПЭ]  [ПЭ]
        │память │память │память │память
```

## 49. Виды ВС класса SIMD: ассоциативные ВС и систолические ВС (концептуальные схемы и принципы работы).
*Нужны **концептуальные схемы**.*
- **Ассоциативные ВС** — **ассоциативный процессор** на базе **АЗУ** (ассоциативного ЗУ): доступ к данным не по адресу, а по **отличительным признакам в самом операнде**. Две особенности (отличие от обычного АЗУ): наличие **средств обработки данных** и **мультизапись** (параллельная запись во все ячейки, где совпал ассоциативный признак).

```
признак поиска ─► [сравнение со ВСЕМИ ячейками сразу] ─► совпавшие
```

- **Систолические ВС** — однородная среда из ПЭ, сочетает свойства **конвейерной и матричной** обработки:
  - данные **ритмично прокачиваются** от ПЭ к ПЭ без запоминания промежуточных результатов;
  - каждый элемент данных читается из памяти **однократно**, используется столько раз, сколько нужно;
  - ПЭ однотипны, связи локальные.
- **Конфигурации матриц:** линейная, прямоугольная, гексагональная, трёхмерная. Пример ПЭ: `c_вых = c_вх + a_вх × b_вх` (умножение матриц).

```
данные → [ПЭ]→[ПЭ]→[ПЭ]→ результат
          ↑   ↑   ↑
        ритмичный поток, ПЭ считает и передаёт дальше
```

## 50. Виды ВС класса MIMD: PVP и MPP (схемы построения, принципы работы).
*Нужны **схемы и принципы**.*
- **PVP (Parallel Vector Processor)** — **SMP-система**, где роль ПЭ играют **векторно-конвейерные** процессоры, связанные широкополосным коммутатором типа **«кроссбар»** с разделяемой памятью. Число процессоров: типично **8–16**, до 512. Cray, NEC.

```
[вект.ЦП][вект.ЦП][вект.ЦП]
        └─ коммутатор ─┘
        [ общая память ]
```

- **MPP (Massively Parallel Processing)** — **массово-параллельная**: тысячи узлов (NORMA, обмен **сообщениями**). Узел содержит: процессор, локальный банк ОП, **2 коммуникационных процессора (маршрутизатора)** — отдельно для команд и данных, диски/устройства ВВ. **Хост-компьютер** — ядро системы (планировщик заданий). На каждом узле своя ОС (или урезанная). Отлично масштабируется, но сложное ПО.

```
[узел][узел][узел]…тысячи… каждый = ЦП+память
    └────── высокоскоростная сеть ──────┘
```

## 51. Виды ВС класса MIMD: Кластерные ВС (схема построения, топологии ВС, характеристики топологий).
*Нужны **схема, топологии, характеристики топологий**.*
- **Кластер** — группа взаимно соединённых **самостоятельных** узлов, работающих совместно как единый ресурс (иллюзия единой ВМ). Дешевле MPP (готовые ПК + сеть). Связь — обмен сообщениями через коммутатор (switch).
- **Преимущества (4):** абсолютная масштабируемость (десятки узлов-мультипроцессоров), наращиваемая масштабируемость (добавление узлов малыми порциями), высокий **коэффициент готовности** (отказ узла не валит кластер), низкое **цена/производительность**.
- **Кластеры и созвездия:** N узлов, M процессоров в узле — если N < M это кластер, если N > M — **созвездие**. Топология «**Fat-tree**» (толстое дерево) — частая для суперкластеров.

```
[узел][узел][узел]
    └── сеть (коммутатор) ──┘  каждый узел — целый компьютер
```

- **Топологии сети:** шина, кольцо, звезда, решётка (mesh), тор, гиперкуб, дерево, полносвязная.
- **Характеристики топологий:**
  - **Диаметр** — макс. расстояние между узлами (определяет задержку).
  - **Связность (connectivity)** — число путей между узлами (отказоустойчивость).
  - **Ширина бисекции (bisection width)** — мин. число линий при разрезе сети пополам (пропускная способность).
  - **Стоимость** — общее число линий связи.

## 52. Виды ВС: dataflow и reduction (принципы работы, пример потокового графа, классификация потоковых ВС).
*Нужны **принципы, потоковый граф, классификация**.*
- **Потоковые (dataflow)** — **управление данными**: команда выполняется, как только готовы её **операнды** (нет счётчика команд, нет PC). Естественный параллелизм. Программа = **потоковый граф**.

```
    a  b   c  d
    \ /    \ /
    (+)    (×)   ← узлы срабатывают, когда пришли операнды
      \    /
        \   /
        (−) ──► результат
```

- **Редукционные (reduction)** — **управление по запросу**: вычисление запускается, когда его результат **затребован** другим (ленивые вычисления, demand-driven).
- **Классификация потоковых:** статические (1 токен на дуге) и динамические (с метками — несколько токенов).

## 53. Перспективные типы процессоров ЭВМ (краткое описание ассоциативных, клеточных, нейронных процессоров, процессоров с многозначной логикой, квантовых компьютеров).
- **Ассоциативные** — доступ к памяти по содержимому, параллельный поиск.
- **Клеточные (ДНК-процессоры)** — вычисления на молекулах ДНК, массовый параллелизм химических реакций.
- **Нейронные (нейропроцессоры/NPU)** — структура из нейронов, параллельная обработка, обучение, для ИИ/распознавания.
- **С многозначной (нечёткой, fuzzy) логикой** — оперируют не «0/1», а степенями истинности через **функции принадлежности**; реализуют **механизм нечёткого вывода**. Для задач с неопределённостью.
- **Квантовые** — кубиты в **суперпозиции** (0 и 1 одновременно) + **запутанность** → экспоненциальный параллелизм для некоторых задач (факторизация, поиск).

## 54. Методы поддержания когерентности кэш-памяти в ВС (перечень методов, общая схема, протокол MESI: состояния и граф переходов).
*Нужны **общая схема** и **граф переходов MESI**.*
- **Проблема когерентности** — в SMP у каждого ЦП свой кэш; одна ячейка ОП может иметь разные копии → нужно согласование.
- **Способы:**
  - программные (компилятор + ОС, некэшируемые данные);
  - протоколы сквозной / обратной записи;
  - **запись с аннулированием (write invalidate)** — копии блока в других кэшах помечаются недостоверными (бит достоверности → 0);
  - **запись с обновлением (write update)** — запись дублируется во все кэши с копией (широковещательно);
  - разделяемая кэш-память; стандарт SCI.
- **Аппаратные механизмы реализации:**
  - **Снупинг (наблюдение, snooping)** — контроллер каждого кэша следит за шиной; процессоры широковещательно шлют запросы, локальный контроллер аннулирует/обновляет свою копию.
  - **Справочниковый (directory)** — централизованный справочник в ОП хранит, у кого какие копии (для больших систем без общей шины).
- Предшественник MESI — **протокол однократной записи (write-once)**: состояния I (Invalid) / V (Valid) / R (Reserved, однократное изменение, учтено в ОЗУ) / D (Dirty).
- **Протокол MESI** — 4 состояния строки кэша:
  - **M (Modified)** — изменена, только здесь, не совпадает с ОП («грязная»).
  - **E (Exclusive)** — только здесь, совпадает с ОП (чистая).
  - **S (Shared)** — есть копии в других кэшах, совпадает с ОП.
  - **I (Invalid)** — недействительна.

```
        чтение(miss, есть у других)
    I ───────────────────────────► S
    │ чтение(miss, ни у кого)    │ запись (своя)
    │                ▼
    └──────────► E ───запись───► M ◄┘
                │        │
        чужая запись→I  чужое чтение→S
```
- **Принцип:** запись разрешена только из состояния M или E; перед записью в S — рассылается инвалидация другим кэшам (→ их строки в I), своя → M.

## 55. Современные суперкомпьютеры: характеристики и примеры
*Метрика — производительность в **PFlop/s** на тесте LINPACK: `Rmax` (реальная) и `Rpeak` (пиковая); рейтинг **TOP500** (top500.org).*
- **Суперкомпьютер** — система максимальной производительности; современные — **экзафлопсные** (≥ 10¹⁸ Flop/s), **гибридные** узлы CPU + GPU-ускорители, быстрая сеть (Slingshot, InfiniBand).
- **TOP500 (ноябрь 2023), первая тройка:**
  1. **El Capitan** (США, HPE Cray, **AMD EPYC 4-го пок. + AMD Instinct MI300A**) — **1.809 EFlop/s**, ~11.3 млн ядер, 29 МВт, 2024 г.
  2. **Frontier** (США, HPE Cray, **AMD EPYC + Instinct MI250X**) — ~1.35 EFlop/s, первый экзафлопсный (2022).
  3. **Aurora** (США, HPE Cray, **Intel Xeon Max + Intel GPU Max**) — ~1.0 EFlop/s.
  - Также: **Fugaku** (Япония, ARM **A64FX**, без GPU), Eagle (Microsoft, NVIDIA H100), JUPITER (Германия, NVIDIA GH200).
- **Российские (в TOP500):** **Червоненкис**, Галушкин, Ляпунов (Yandex, AMD EPYC + NVIDIA A100), **Christofari / Christofari Neo** (СберCloud, NVIDIA DGX).
- **Пути развития:**
  - эволюция (экстраполяция предыдущих лет);
  - **Grid-технологии и облака**;
  - параллелизм многих уровней;
  - **сопроцессоры-ускорители** (неоднородная структура);
  - обработка на **ПЛИС/FPGA**;
  - специализация на заказных микросхемах.
- **Основные сложности:**
  - задержки и узкая полоса «процессор–память» и межпроцессорных связей;
  - издержки ОС, растущие с числом процессоров;
  - трудности распараллеливания;
  - слабая поддержка параллелизма языками программирования.

## Шпаргалка-минимум (если совсем мало времени — выучи это)

- **Флинн:** SISD / SIMD / MISD / MIMD (по потокам команд × данных).
- **Амдал:** `S = 1/(f + (1−f)/n)`, потолок `1/f`. Последовательная доля всё губит.
- **Память ВС:** UMA (общая, равный доступ, SMP) · NUMA (распределённая, общее адр., неравный доступ) · NORMA (только своя память + сообщения, кластеры/MPP).
- **SIMD** = векторные/матричные/ассоциативные/систолические. **MIMD** = PVP/MPP/кластеры.
- **MESI:** Modified / Exclusive / Shared / Invalid — когерентность кэшей.
- **CISC** (микропрограммное УУ, сложные команды) vs **RISC** (аппаратное УУ, простые, 1 такт, load/store) vs **VLIW** (параллелизм задаёт компилятор).
- **Фон Нейман:** двоичное кодирование, программное управление, однородность памяти, адресуемость.
- **Кэш-отображение:** прямое / ассоциативное / множественно-ассоциативное.
- **DMA** — обмен ПУ↔память минуя ЦП.
- **Intel vs AMD:** AMD первой ввела 64-бит и встроенный контроллер памяти; сейчас Intel = гибрид P+E ядра, AMD = чиплеты + Infinity Fabric + 3D V-Cache.
